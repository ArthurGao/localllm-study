RAG（检索增强生成）技术文档
===========================

一、什么是 RAG

RAG（Retrieval-Augmented Generation，检索增强生成）是一种将信息检索与文本生成相结合的 AI 技术。
它的核心思想是：在生成回答之前，先从知识库中检索相关信息，然后将检索到的内容作为上下文提供给大语言模型，从而生成更准确、更有依据的回答。

RAG 解决了大语言模型的两个关键问题：
1. 知识时效性：模型训练数据有截止日期，无法获取最新信息
2. 幻觉问题：模型可能生成看似合理但实际错误的内容

二、RAG 的核心流程

RAG 的工作流程分为三个主要阶段：

1. 索引阶段（Indexing）
   - 文档加载：将 PDF、Word、网页等格式的文档读取为文本
   - 文本分块：将长文档切分为较小的文本块（通常 500-1000 个字符）
   - 向量化：使用 Embedding 模型将文本块转换为高维向量
   - 存储：将向量和原始文本存入向量数据库（如 ChromaDB、Pinecone、Weaviate）

2. 检索阶段（Retrieval）
   - 将用户的问题也转换为向量
   - 在向量数据库中进行相似度搜索
   - 返回与问题最相关的 Top-K 个文本块

3. 生成阶段（Generation）
   - 将检索到的文本块与用户问题组合成 Prompt
   - 发送给 LLM 生成回答
   - 模型基于提供的上下文生成有依据的回答

三、Embedding 模型

Embedding 模型负责将文本转换为固定维度的向量表示。好的 Embedding 模型应该能让语义相似的文本在向量空间中距离更近。

常用的 Embedding 模型：
- nomic-embed-text：轻量级，适合本地运行，768 维
- text-embedding-ada-002：OpenAI 的模型，1536 维
- bge-large-zh：专门针对中文优化的模型

选择 Embedding 模型的考虑因素：
- 维度越高，表达能力越强，但存储和计算成本也越高
- 中文场景建议选择针对中文优化的模型
- 本地运行建议使用 nomic-embed-text（通过 Ollama）

四、向量数据库

向量数据库是专门用于存储和检索高维向量的数据库。与传统数据库不同，它支持基于相似度的搜索。

ChromaDB 是一个轻量级的开源向量数据库，特点：
- 支持本地运行，无需部署服务器
- 支持持久化存储到磁盘
- 与 LangChain 深度集成
- 支持多种距离度量：余弦相似度、欧氏距离、内积

其他常见的向量数据库：
- Pinecone：云托管，免运维
- Weaviate：支持混合搜索（向量 + 关键词）
- Milvus：高性能，适合大规模数据
- FAISS：Facebook 开源，纯向量搜索库

五、文本分块策略

文本分块是 RAG 中至关重要的一步，分块质量直接影响检索效果。

常见分块方法：
1. 固定大小分块：按字符数或 token 数固定切分
2. 递归字符分割：按自然边界（段落、句子）递归分割，推荐方法
3. 语义分块：根据语义相似度动态切分
4. 按文档结构分块：利用标题、章节等结构信息

关键参数：
- chunk_size（分块大小）：建议 500-1000 字符
  - 太小：缺乏上下文，检索到的片段不完整
  - 太大：包含无关信息，检索精度下降
- chunk_overlap（重叠大小）：建议 50-100 字符
  - 防止关键信息在分块边界被截断
  - 相邻块之间共享部分内容

六、Prompt 工程

RAG 中的 Prompt 设计直接影响生成质量。一个好的 RAG Prompt 应该：

1. 明确角色和任务
2. 提供检索到的上下文
3. 规定回答的约束条件（如"仅根据上下文回答"）
4. 处理上下文不足的情况

示例 Prompt 模板：
```
你是一个专业的问答助手。请根据以下参考资料回答用户问题。
如果参考资料中没有相关信息，请说明无法回答。

参考资料：
{context}

用户问题：{question}
```

七、RAG 的常见问题与优化

1. 检索质量差
   - 原因：分块不合理、Embedding 模型不适合
   - 优化：调整 chunk_size、使用更好的 Embedding 模型

2. 答案不准确
   - 原因：检索到的文档不相关、Prompt 设计不当
   - 优化：增加重排序步骤、优化 Prompt

3. 上下文窗口限制
   - 原因：检索到的文档总长度超过模型的上下文窗口
   - 优化：减少 top_k、使用压缩技术、选择大上下文模型

4. 多文档冲突
   - 原因：不同文档提供矛盾信息
   - 优化：添加来源标注、使用多跳推理
